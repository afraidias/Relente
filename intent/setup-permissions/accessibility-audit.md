# Accessibility investigation

On 2026-11-04, an exploratory `XCUIApplication.performAccessibilityAudit()` UI test on the initial setup screen failed with “Element has no description”. Its diagnostic identified an unnamed disabled group containing the entire window, including the heading, text and both buttons. A comparison using a fresh archive of `origin/main`, the same test and no other Relente test instances also failed with the same message; its element capture showed the original setup screen and full-window group. This establishes that the audit warning also occurs on the baseline, but does not establish its root cause or that it is harmless. A label on the setup content and a conditional label on the assistant root did not resolve it; both attempts were removed. No audit warning was suppressed.

The audit can be reproduced from a UI test that launches `XCUIApplication.relente(extraArguments: ["-sampleHelper", "notInstalled"])`, waits for “Set Up Relente”, and executes `try app.performAccessibilityAudit()`. The exploratory failing test is not included as a CI test; this report preserves the result and the PR remains draft while the warning is unresolved.

With macOS keyboard navigation temporarily enabled, Tab focused Install Helper and then Open Full Disk Access Settings. The original keyboard setting was restored. Clicking the latter opened Full Disk Access without changing any permission. English initial and error states were captured in light mode with Reduce Motion enabled. In a separate slow, simulated registration, the progress indicator remained animated despite Reduce Motion; the footer was changed to omit the spinner, and a subsequent manual check confirmed that the disabled installing button contained static text only. Reduce Motion and appearance were restored afterwards.

A macOS 27 XCTest VoiceOver-service attempt timed out enabling VoiceOver. The system switch was manually enabled for diagnosis, but automatic approval review rejected rerunning the test because the test would consider VoiceOver already enabled and might leave the setting changed. VoiceOver was then restored to off. The owner subsequently reported that VoiceOver read the title, both callouts and both buttons, and that both installation-start and helper-ready changes were announced during the simulated flow. VoiceOver was restored to off. This owner-reported check does not resolve the separate audit warning. No authorization or disk permission was changed.
